- Accepted — 031c93c4 info 5, `FarmRewards._credit`: a same-epoch scrap/award credit back-dates the maturity of the later settlement credit for that epoch by up to one epoch (`src/FarmRewards.sol:486`, `if (v.amount == 0 || at < v.at) v.at = uint64(at);`). Launch L3 (FarmRewards pin, role 1). The v3.14 vintage-timestamp rule keeps, per 32-slot vintage, the earliest `at` of all credits for the same epoch (line 486). Settlement credits pass `at = e.end` (lines 418, 423), but scrap (line 561) and award (line 575) credit the current epoch with `at = block.timestamp`, which is earlier than `e.end`. When a player scraps during epoch N and N is settled later, the settlement credit merges into the same slot and inherits the scrap timestamp, so its 7-day tax age starts up to 6 hours early. `taxBps` falls 1500 bps over 7 days, so the mispricing is at most about 54 bps of the settlement credit, in the player favour and self-triggered; reserved accounting is unchanged (`pending == matured + sum(vintages)` still holds). `test/AuditV314.t.sol` `testLaterSameEpochCreditKeepsEarlierTaxVintage` shows the earliest-timestamp merge is intended for two awards in one epoch; this note only records that it also lets a current-epoch scrap/award pull a later settlement credit age forward. Launch judge: would not block. Fix if wanted: pass `epochs[epoch].end` as `at` for scrap and award credits; changes the FarmRewards pin (role 1) only. Reproduction: epoch N open (start S, end S+6h), player p has committed weight and an unequipped item; at t = S+10min p calls `FarmCore.scrap(id, 0)` with `scrapAllowance > 0`: `_credit(p, x, N, S+10min)` sets `vintages[N%32] = {epoch N, at S+10min, amount x}`; after N closes and p settles N at S+6h+1min, `_reward` credits y via `_credit(p, y, N, S+6h)`: `at` (S+6h) is not < `v.at` (S+10min), so `v.at` stays S+10min and `v.amount = x+y`; at a claim at S+10min+7d exactly, `_consume` sweeps the slot as fully matured (`block.timestamp >= at + 7 days`) and taxes y at 500 bps; with `at = S+6h` the age would be 7d - 5h50m and `taxBps = 2000 - 1500*(7d-5h50m)/7d` = about 552 bps. Verified by code reading of lines 418, 423, 486, 561, 575. Accepted as is: the FarmRewards pin stays byte-identical.
